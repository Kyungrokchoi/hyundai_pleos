# 승객 웹 (passenger-web)

모바일 우선 한국어 Next.js 앱. 승객이 QR로 참여하고, 타고 내릴 때 버튼을 누르고, 정산 근거를 보고 승인/이의 제기를 한다. 결제·송금은 없다.
소스: [`passenger-web/`](../passenger-web/) · 토큰: [`design-tokens.md`](design-tokens.md) · API: [`API_CONTRACT.md`](API_CONTRACT.md)

## UX v3 (2026-11-02, 2차 리뷰 진단 후): 출발 전 탑승 · 출처 표기 · 합의 ≠ 송금 · 구간 막대

디자인 리뷰·UX 리뷰·접근성 리뷰 진단(전문가 관점 리뷰이며 실사용자 시험 아님)과 사용자 결정(출발 전 확인 + 운전자 대신 표시 / P0–P1 + 구간 막대 / '금액 합의 완료' + 금액 복사)에 따른 변경. v2 아래 표는 이력으로 남긴다.

| 항목 | 변경 |
|---|---|
| 탑승 (P0) | `INVITING`에서도 `탔어요`(주요 행동). 출발 전 탑승은 첫 주행거리 스냅샷부터 계산(서버 `PRE_DEPARTURE`). 주차 중 `잘못 눌렀어요`로 승객이 직접 취소. 대기 화면은 "출발 전까지 열어 두세요"(이전 "닫아도 괜찮아요"는 탑승 누락을 부름) |
| 출처 표기 (필수 규칙) | 배지에 **코드 + 쉬운 말**: `PLEOS · 차량에서 읽은 값` / `MANUAL · 직접 입력` / `DEMO · 가상 데이터`. 정산 화면 금액 바로 아래 출처 줄을 **항상** 표시(출처별 배지 1개 + 해당 항목: 거리·연비/전비·유가/전기요금·통행료·주차비). 단가는 API에 출처 필드가 없고 비용 규칙에서 운전자가 입력하는 값이라 `MANUAL` 로 표기 |
| 합의 ≠ 송금 | `정산 완료` → `금액 합의 완료`. 확정 후 "송금은 평소 쓰는 앱으로 {운전자}님께 직접 보내 주세요. 모아타는 돈을 옮기지 않아요." + 주요 행동 `{금액}원 복사`(숫자만 복사, 실패 시 직접 복사 안내, `role=status`로 결과 안내). 승인 버튼 아래 "이 금액에 동의해요 · 돈은 나가지 않아요". 승인 어휘는 `승인` 하나로(승인할게요/승인했어요/승인 전/모두 승인하면 합의돼요) |
| 다시 시도 | 이동 화면(탑승·하차)과 정산(승인·이의)의 `다시 시도`가 **실패한 동작을 다시 보냄**(이전엔 오류만 닫음). 재시도한 하차가 이미 서버에 반영돼 `NOT_ON_BOARD`면 성공으로 처리 |
| 구간 막대 `RideStrip` | 0→D km 축, 사람마다 한 줄(운전자 먼저, 내 줄은 청록), 내린 지점 표시, 각 줄에 같은 내용의 글("0–13km 탑승 · 13km에서 내림") — 막대는 `aria-hidden`, 글이 대체 텍스트. 이동 화면에선 실시간("지금 16km"), 내린 뒤 큰 숫자는 **내가 탄 거리**. 정산 화면에선 "내 몫은 이렇게 나왔어요"에 막대 + 구간별 나눗셈("1,950원 ÷ 3명 = 650원", 나눠떨어지지 않으면 "약" + 서버의 1원 배분 설명) + 비용 항목 + 합계(서버 값). 계산은 표시용이며 금액은 서버 값만 씀 |
| 기타 | `←`·`★` 글리프 → SVG 아이콘. 텍스트 링크 들여쓰기 제거. 그룹 화면은 이력에 DEMO가 있으면 DEMO 띠. `scroll-padding`(고정 바에 포커스 가림 방지), `::selection`·caret 색 |

검증(2026-11-02, VERIFIED_MOCK — 실제 백엔드 :8010 + 프로덕션 빌드 :3100, 차량은 e2e 스크립트가 대신함): `npm run lint` 0건 · `tsc` 0건 · Vitest **103 passed** · Playwright **12 passed**(axe 태그에 `wcag22aa` 추가, 위반 0) · 빌드는 e2e가 `NEXT_DIST_DIR=.next-e2e` 로 수행(데모 `.next` 미변경) · 디자인 린트 `passenger-web/src` → `[]`(정규식 기반 소스 스캔이라 과소 집계 가능). 캡처: [`evidence/web-v3/`](evidence/web-v3/)(MANUAL 모드 — 테스트 운전자가 입력한 값이라 PLEOS로 표기하지 않음). 정산 화면 높이 957 → 1,169px(아코디언 닫힘; 구간 막대·구간별 나눗셈이 아코디언 밖으로 나옴. e2e 상한 1,300px, 금액·문장·출처 줄이 첫 화면 안에 있는지 검사).
미해결: 그룹 이력의 금액은 API(`HistoryItem`)에 개인 몫 필드가 없어 이동 전체 금액으로 남음. 실제 스크린리더(VoiceOver/TalkBack) 시험은 NOT_RUN.

## UX v2 (2026-11-02): "답을 먼저, 근거는 접어서"

사용자 평가("디자인과 UX가 나쁘고 불편하다")에 따라 화면을 다시 설계했다. 문제는 ① 정산 화면이 길고(2,561px) 주요 행동이 맨 아래, ② 같은 4문단 안내가 모든 화면 끝에 반복, ③ 같은 무게로 외치는 구획이 너무 많음, ④ 굵은 검은 윤곽선·오프셋 그림자로 시끄러움, ⑤ 전문 용어("차량 실측", "경계", "확인 전", 주행계 숫자)였다.

| 화면 | 이전 → 이후 |
|---|---|
| 정산 `/trip/[id]/bill` | 한 화면 답: "내가 운전자에게 줄 금액" + 64px 숫자 + 한 문장("24km 중 13km를 함께 탔어요.") + 한 줄 고지(+자세히). **고정 하단 바**에 `승인할게요`(노랑, 유일) + `이의 있어요`. 계산식·구간·내 몫 근거 / 모두의 몫 / 공유는 닫힌 아코디언 3개. 이의는 대화상자(사유 필수). **문서 높이 2,561px → 957px**(전부 펼쳐도 2,086px) |
| 이동 `/trip/[id]` | 현재 상태 한 줄(34px) + 큰 거리 + 단순 아바타 목록. 고정 하단 바에 해당 행동 **하나**(`탑승했어요`/`내렸어요`/`정산 보기`). "우리 모아 보기"는 텍스트 링크. **내린 직후엔 큰 `탑승했어요`를 없애고** "내리셨어요 · 출발 후 13km 지점에서 내렸어요" 안내 + 조용한 `다시 탔어요` 링크. 높이 1,167 → 957px |
| 참여 `/join` | 그룹·운전자 → 한 줄 고지 → `정산 규칙 보기 (N가지)` 접힘 → 닉네임 → **동의 두 개는 각각 따로, 무엇에 동의하는지 라벨에 명시**("정산 규칙 N가지를 확인했고 동의해요") → 고정 하단 큰 버튼. 두 동의 전에는 비활성 + 이유 한 줄. 높이 1,148 → 915px |
| 홈 `/` | 소개 + 한 줄 고지 + 이어보기(주요 버튼은 최대 1개). 1,081 → 853px |
| 그룹 `/group/[id]` | 모아·진행바(청록)·배지·이력·데모 쿠폰("시연용 · 실제 교환 불가"). 페이지 끝 `안내 보기`. 1,183 → 1,152px |

공통:
- **법적 안내는 글자 그대로**, 위치만 이동: 정산·참여·홈에는 "추정 금액이에요 · 결제·송금은 하지 않아요 + 자세히"(펼치면 서버 원문 전체), 이동·그룹에는 페이지 끝 `안내 보기`(같은 원문). 그룹 화면에는 이 기기가 마지막으로 본 서버 원문을 그대로 저장해 두었다가(`moata.notices.v1`) 보여 준다. 본 적이 없으면 링크를 숨긴다.
- 서버 경고 중 `DEMO_DATA`·`MANUAL_DATA` 는 데이터 출처를 되풀이할 뿐이라 배너로 띄우지 않고(DEMO 띠·출처 칩이 이미 알림) 안내 원문 목록에 포함한다. 그 밖의 경고(`ODOMETER_STALE` 등)는 그대로 눈에 보이게 표시.
- 값의 출처는 "차량에서 읽은 값 / 직접 입력한 값 / 연습용 가상 데이터"로 쓰고, 정산의 "어떻게 계산했어요?" 안에서 한 번만 설명한다. 승인 상태는 "확인했어요 / 기다리는 중 / 이의가 있어요"(아이콘 + 글자).
- 주행계 값(34,216km)은 승객에게 보이지 않는다. 구간·하차 지점은 **출발 이후 거리**("출발 후 0 → 13km")로 표시(표시용 뺄셈, 돈 계산 아님).
- 화면당 노란 주요 행동은 최대 1개(e2e가 각 화면에서 `.btn--primary` 개수를 검사). 터치 영역 48px+, 주요 행동 56px, 본문 16px+.

### 화면(라우트)

| 경로 | PRD | 내용 |
|---|---|---|
| `/` | — | 소개·사용 순서, 참여 정보가 있으면 이어보기/나가기 |
| `/join` | P01 | 토큰은 **URL 프래그먼트**(`#<token>`)에서 읽고 주소창에서 즉시 지움 → 초대 미리보기 → 닉네임 + 동의 2개 → 참여 요청 → 승인 대기(3초 폴링, `GET /groups/{id}/me` 로 승인·거절 감지) |
| `/trip/[id]` | P02 | 3초 폴링(ETag/If-None-Match), 상태·거리·출처 칩, **DEMO 상시 띠**, **내 것만** 탑승/하차(하차는 2단계 확인) |
| `/trip/[id]/bill` | P03 | 서버 값 그대로: 내 몫·한 문장·산식·구간·모두의 몫·승인 현황, 승인/이의 제기(사유 필수), 복사·공유(이름 가리기 기본 켜짐) |
| `/group/[id]` | P04 | 모아(레벨·XP·기분), 배지, 이동 이력, 데모 쿠폰 |

상태별 화면: 로딩 스켈레톤, 빈 상태, 오류+재시도, 오프라인/오래된 데이터(마지막 데이터를 유지하고 안내), 권한 없음(401/403/404), 초대 만료/무효(404/410), DEMO, 승인 대기/거절, 이전 정산안(SUPERSEDED).

## API 사용

타입은 `contracts/openapi.yaml` → `npm run gen:api` → `src/api/schema.d.ts` (생성물, 커밋 대상) → `src/api/types.ts` 가 별칭으로 재노출. 계약이 바뀌면 `tsc` 가 깨져서 알려 준다. 호출은 `src/api/client.ts` 한 곳에서만 `fetch` 한다.

- 사용: `POST /invites/preview|accept`, `GET /groups/{id}/me`, `GET /trips/{id}/summary`, `POST /trips/{id}/participants/{me}/board|alight`, `POST /settlements/{id}/approvals`, `GET /groups/{id}/character|history|rewards`, `POST /auth/logout`.
- API 주소: `NEXT_PUBLIC_API_BASE`, 비어 있으면 **현재 페이지 호스트:8000** 으로 계산(같은 와이파이의 휴대폰이 PC의 API에 닿도록).
- 화면에 보이는 금액·합계·산식은 **전부 서버 값**이다. 클라이언트는 돈을 다시 계산하지 않는다(몫 합계가 총액과 다르면 경고 띠만 띄운다). 이동 거리는 서버 `distance_km`, 진행 중에는 표시 전용으로 `최신 주행거리 − 시작 주행거리` 를 보여 준다.

## 보안·개인정보

- 초대 토큰: 쿼리스트링에 두지 않음(프래그먼트 → `history.replaceState` 로 제거), 탭 범위 `sessionStorage` 에만 임시 보관, 참여 성공 시 삭제(만료된 초대는 화면의 `이 초대 정보 지우기` 로 삭제). `/invites/*` 는 본문(POST body)으로만 전달. e2e가 "모든 네트워크 요청 URL에 토큰이 없다"를 검증한다.
- 로그인 토큰: `localStorage`(쿠키 없음 → CSRF 면 없음). 외부 스크립트·분석·CDN 없음, `dangerouslySetInnerHTML` 없음(React 기본 이스케이프). `이 기기에서 나가기` 는 서버에서 토큰을 **폐기**(`POST /auth/logout`)한 뒤 로컬을 지운다. 401 을 받으면 죽은 세션을 자동으로 지운다.
- 헤더(`next.config.ts`): `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, 프로덕션 빌드에 CSP(`connect-src` 는 `NEXT_PUBLIC_API_BASE` 가 빌드 시 설정되면 그 출처로 고정, 아니면 `http(s)://*:8000`).
- 저장 정보 안내: 닉네임과 탑승 구간 주행거리뿐(위치·연락처·차량번호 저장 안 함)을 참여 화면과 홈에 명시.
- 공유 텍스트는 서버 숫자를 그대로 복사하며 이름 가리기(참가자 A/B…)를 기본으로 제공. DEMO 면 공유 글에도 표시.
- 고지: 추정치, 결제·송금 없음, 적법성 비보장 문구는 서버가 준 원문을 그대로 보여 준다.

## 계약 관련 발견

1. **(해결됨) 거절을 알 수 없음.** 서버에 `GET /groups/{gid}/me`(호출자 본인의 멤버십, 모든 상태)가 추가됐고 승인 대기 화면은 이제 그것으로 승인·거절을 구분한다(`src/lib/membership.ts`, 단위 테스트 포함).
2. **타인의 이동은 404.** 그룹 비멤버가 `/trips/{id}/summary` 를 열면 403이 아니라 404(존재 은닉). 화면은 "찾을 수 없어요"로 안내하며 403도 같은 방식으로 처리한다.
3. **`POST /auth/logout` 이후 같은 토큰은 401**(e2e로 확인) — 나가기가 서버 폐기까지 이어진다.
4. **CORS**: 개발 기본값은 `localhost:3000`, `127.0.0.1:3000` 뿐이다. 휴대폰(LAN)에서 열려면 서버에 `MOATA_CORS_ORIGINS=http://<PC-LAN-IP>:3000` 를 추가해야 한다. `If-None-Match` 허용·`ETag` 노출은 설정돼 있고, 클라이언트는 ETag 헤더가 안 보여도 본문 `revision` 으로 대체한다.
5. **서버 고지 문구에 전문 용어**: 데이터 출처가 PLEOS 일 때의 안내 "운전자의 차량 앱이 Pleos SDK에서 읽어 보고한 값입니다(서버가 차량에서 직접 검증하지는 못합니다)."에 "Pleos SDK"가 들어 있다. 법적/검증 한계를 알리는 원문이라 **글자 그대로 두었다**(접힌 "자세히" 안). 승객 눈높이로 바꾸려면 서버 `MODE_NOTICE["PLEOS"]` 를 고쳐야 한다(예: "차량이 알려 준 값이며, 서버가 직접 확인한 값은 아닙니다"). 내용 판단은 백엔드 쪽 몫.
6. `schema.d.ts` 는 `--default-non-nullable false` 로 생성한다(기본값이 있는 요청 필드를 선택 항목으로). 응답의 기본값 필드(`CharacterOut.name/note_ko`, `GroupOut.members`)는 타입상 선택 항목이 된다.

## 알려진 한계

- Playwright e2e 는 데스크톱 Chromium 에서 412×915 폰 뷰포트를 **에뮬레이션**한 것이다. 실제 휴대폰 브라우저, Safari/iOS(주소창 높이 변화·소프트 키보드와 하단 고정 바의 상호작용, 홈 인디케이터), 스크린리더(VoiceOver/TalkBack) 직접 사용, 실제 LAN 접속, QR 카메라 스캔은 **NOT_RUN**.
- 하단 바는 `env(safe-area-inset-bottom)` 을 반영하지만 `viewport-fit=cover` 는 쓰지 않는다(쓰지 않으면 iOS 가 뷰포트를 안전 영역 안으로 제한해 겹침이 없다). 실제 iPhone 에서는 확인하지 못했다.
- `navigator.share`/클립보드는 e2e에서 동작을 확인하지 않았다(단위 테스트는 텍스트 생성만 검증).
- 승인 대기·정산·이동 화면의 폴링은 3~4초 간격이다(웹소켓 없음). 백그라운드 탭은 폴링을 멈추고 다시 보일 때 즉시 갱신한다.
- `next dev` 를 LAN 에서 열 때는 `ALLOWED_DEV_ORIGINS=<PC IP>` 가 필요할 수 있다. 시연은 프로덕션 모드(`npm run build && npm run start`)를 권장한다.
- 차량 화면 UX 제한(주행 중 숨김)은 이 앱의 범위가 아니다(승객 휴대폰용).

## UX v3b (재진단 P1 반영, 2026-11-02)

독립 재진단(디자인 리뷰)의 P1을 고쳤다.

- **`잘못 눌렀어요` = `alight` + `{undo: true}`**: 운전자의 출발이 먼저 처리돼도, 차가 움직이기 전이면 서버가 탑승 기록을 지운다(0 km 탑승으로 통행료가 나가지 않음). `내렸어요` 는 그대로(`useRideActions` 의 `RideAction = board | alight | unboard`).
- **운전자가 기록한 탑승을 승객에게 보여 줌**: 내 구간에 `opened_by === "DRIVER"` 가 있으면 이동 화면에 “운전자가 출발할 때 탑승으로 기록했어요. 탄 시점이 다르면 정산서에서 이의를 남겨 주세요.”, 구간 막대 글(스크린리더 포함)에 `· 운전자가 기록`.
- **정산서 내역이 더해지게**: 금액 칸에는 실제로 더하는 값(연료 비용 내 몫, 항목별 몫, 합계)만. 구간 나눗셈은 그 값 아래 흐린 줄(`0–13km 구간 · 1,950원 ÷ 3명`, 구간이 하나면 결과를 반복하지 않음).
- **통행료 이유**: 항목 이름은 `통행료 · 고속도로`, 아래 줄에 `2,400원 ÷ 3명 · 탄 거리와 관계없이 똑같이` / `탄 거리만큼 나눔` / `운전자가 부담`. 나누는 사람 수는 서버 `shares[].items` 에서 센다(추정하지 않음).
- **내린 뒤 제목**: 차는 계속 가도 나에게는 `내렸어요`(다른 승객 화면은 `이동 중`).
