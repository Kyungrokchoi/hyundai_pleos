# 결정 기록 (Decisions)

PRD(`MOATA_Pleos_Official_PRD_TechSpec_v2.md`)와 실제 SDK/환경 사이의 충돌, 그리고 “가장 작고 안전한 구현”을 위해 내린 선택을 기록한다.
구현 지시문이 언급한 별도 지시 문서 파일은 워크스페이스에 없었고 PRD v2 한 개만 존재했다.

## B. 아키텍처 / 범위 선택

1. **저장소 구조:** 지시문의 `apps/*, services/*, packages/*` 대신 **PRD §10 권장 구조**(`car-app/`, `passenger-web/`, `backend/`) + `contracts/`. 지시문이 “PRD와 충돌하면 PRD를 따르라”고 했고 기술적 장애가 없다.
2. **비용 엔진은 서버 한 곳**(`backend/app/services/cost_engine.py`). Kotlin에 복제하지 않는다(드리프트 방지, PRD §10 “권위는 서버”). 차량 앱은 서버가 준 정산안을 표시하고, 오프라인에서는 거리 기록만 한다.
3. **반올림:** 에너지 총액을 원 단위로 **한 번만** 반올림(half-up) → 구간 길이 비례로 최대잉여법 배분 → 구간 내 인원에게 최대잉여법 배분. 동점은 `user_id` 오름차순. 따라서 합계는 항상 정확히 보존되며 1원 편차는 가장 앞선 ID에게 간다(알려진 미세 편향, 문서화).
4. **비용 전제:** 모든 비용은 운전자가 선지출했다고 가정하고 승객 몫 = 운전자에게 줄 금액. 운전자 제외 정책에서도 *승객 없이 달린 구간은 운전자 부담*.
5. **항목별 배분 정책** `EQUAL | DISTANCE_WEIGHTED | DRIVER_ONLY` 를 통행료/주차비마다 명시(일괄 비례 배분 금지).
6. **멱등성:** `Idempotency-Key` 헤더 테이블 대신 **클라이언트 생성 UUID**(그룹·운행·비용 항목·판독값 `event_id`)와 **입력 해시 유일 제약**(정산 리비전), `(trip_id, rule_id)` 유일 제약(XP/배지)으로 구현. 재시도 = 같은 결과.
7. **동기화:** 실시간 채널 대신 **폴링 + ETag(`Trip.revision`)**. 인증된 채널이 하나로 줄고 오프라인 복구가 단순하다.
8. **상태:** `READY` 단계를 유지(PRD §7.1). 승객은 초대 수락 시 규칙에 동의(`rules_ack`)하고 운전자가 승인해야 `ACTIVE`. `INTERRUPTED` 는 스키마에만 있고 서버가 만들지 않는다(차량 앱은 로컬 DB로 복구).
9. **인증:** 이메일/SMS 없는 **임시 게스트 토큰**(불투명 256bit, SHA-256 해시만 저장, 30일). 폐쇄형 테스트용이며 `MOATA_ALLOW_GUEST_AUTH=false` 로 끈다. 초대 토큰은 단기·횟수 제한·해시 저장, URL **프래그먼트**로 전달.
10. **출처 무결성:** `PLEOS`/`DEMO` 출처 연비는 직접 입력할 수 없고(서버 거부) 저장된 센서 판독값에서만 도출. 운행 `data_mode` 와 다른 출처의 판독값은 거부(`SOURCE_MISMATCH`). 수동 교정된 탑승 경계는 `ESTIMATED` 로 표시.
11. **탑승 경계:** 승객이 누른 순간의 서버 보유 *최신 유효 주행거리*. 180초보다 오래된 값이면 `ESTIMATED` + 경고. 좌석/도어 센서로 신원을 추정하지 않는다(PRD §3.2).
12. **보상:** 확정된 운행 + 서로 다른 2인 이상 + 거리>0 일 때만 XP 10, 운행당 1회. 거리·속도·횟수 가속 보상 없음. DEMO 운행도 성장하지만 `data_mode` 를 기록.
13. **Python 3.12** 고정(`uv`): 설치된 3.14는 휠 성숙도 때문에 피함. 의존성은 `requirements*.in` → `uv pip compile` 로 핀 고정.
14. **DB:** 운영 PostgreSQL(Alembic 마이그레이션), 기본 테스트는 SQLite 인메모리. 같은 57개 테스트를 PostgreSQL 16에서도 실행. 이 머신은 Docker 데몬이 꺼져 있어 Homebrew PostgreSQL 16 임시 클러스터를 사용했고 `docker-compose.yml` 은 NOT_RUN.

## C. 환경 선택

- Pleos 이미지는 `sdkmanager` 가 사용자 사이트를 읽지 못해 수동 설치(`docs/emulator-provisioning.md`).
- 릴리스 APK는 서명 키가 없어 만들지 않는다(디버그 APK만).

## D. 차량 앱 도구 체인 (빌드로 확인됨)

- AGP 9.2.1 + Gradle 9.4.1 + **Kotlin 플러그인 2.4.10**(AGP 기본 2.2.10 은 2.4로 빌드된 stdlib·serialization 라이브러리를 읽지 못함) + KSP 2.3.13 + Room 2.8.5. AGP 8.x 폴백은 필요 없었다.
- **UNVERIFIED 매니페스트 선언:** `uses-feature android.hardware.type.automotive`, `distractionOptimized=true` 는 표준 Android Automotive 선언이지만 Pleos 문서에서 요구 사항을 확인하지 못했다(문서에 매니페스트 절 없음). 에뮬레이터에서는 정상 실행됐다. Pleos 앱 등록 심사에서 확인 필요.
- 차량 앱은 비용 엔진을 복제하지 않고 서버 정산을 표시한다(B2).

## E. 리뷰로 바뀐 것 (정확성 리뷰 + AppSec 리뷰, 재현된 결함만 수정)

독립 코드 리뷰 2건(정확성, AppSec)의 보고를 근거로 수정했고, 결함마다 회귀 테스트를 추가했다(`tests/test_hardening.py`, `tests/test_review_fixes.py`, `tests/test_pg_concurrency.py`).

- **돈/정합성:** EQUAL_SPLIT 이 빈 차 구간 비용을 승객에게 물리던 문제(이제 빈 차 구간은 항상 운전자), 0 km 탑승으로 XP/배지를 얻는 문제(실탑승 1 km 이상 필요), 같은 `event_id` 로 다른 종류 판독값이 시작 주행거리가 되던 문제, 판독값 상한이 종료를 막던 문제, 오타 주행거리로 운행을 못 끝내던 문제(운전자가 판독값을 취소 `DELETE /trips/{id}/readings/{event_id}`), 지터로 구간이 뒤집히던 문제, 산식 표시 자릿수.
- **동시성(PostgreSQL에서만 재현):** `lock_trip` 이 낡은 ORM 상태를 돌려주던 문제(`populate_existing`), XP 갱신 소실·첫 지급 충돌(그룹 행 잠금), 동시 같은 운행 생성 500, 한 그룹에 진행 중 운행 2개(부분 유니크 인덱스 + 서비스 검사).
- **보안/프라이버시:** CostItem 전역 PK → `(trip_id, id)`, 동일 문구 404(존재 은닉), 승인 대기자 목록은 운전자·본인에게만, 멤버 결정은 PENDING만, 초대 폐기·로그아웃(토큰 폐기), 바이트 단위 본문 제한(청크 전송 포함)·보안 헤더·문서 끄기 설정, 닉네임 정규화/제어문자 거부, 수치 상한·판독값 그럴듯함 검사, naive/비정상 타임스탬프를 배치 전체 실패가 아닌 항목별 거부(오프라인 큐가 막히지 않게), 감사 로그 잔여물 삭제, 보존 작업이 빈 그룹·만료 토큰·미가입 게스트까지 정리, 정상화된 500 응답.
- **정직성:** `PLEOS` 출처는 “운전자 차량 앱이 보고한 값(서버가 직접 검증하지 못함)”으로 고지(`MODE_NOTICE`). 판독값의 `source/quality/captured_at` 은 클라이언트 주장이다.
- 차량 앱: 에뮬레이터에서 `NetworkOnMainThreadException` 크래시 발견 → 수정.
- 웹: 새 `GET /groups/{id}/me` 로 대기/거절을 구분(추측 우회 코드 삭제).

### 알려진 잔여 위험 (구현하지 않음)

- **요청 속도 제한 없음**(`/auth/guest`, `/invites/*`, 판독값 배치). 리버스 프록시/WAF 에서 제한해야 한다.
- 판독값 출처는 서명되지 않는다(차량별 키 등록 필요 → 계약 단계).
- 멤버 자진 탈퇴·계정 삭제 API 없음(그룹 소유자가 그룹을 삭제하면 모든 데이터 삭제).
- 거절된 사람이 새 게스트로 다시 신청할 수 있다(실명/전화 미수집 설계의 귀결).
- 청크 전송이 한도를 넘는 경우 413 이지만 핸들러가 이미 일부 실행됐을 수 있다(Content-Length 가 있으면 사전 차단).
- 의존성 CVE 스캔(`pip-audit`)은 실행하지 않았다. 웹은 `npm audit --omit=dev` 0건.

## F. UX v3 (리뷰 기반 진단 후, 사용자 선택 반영 — 2026-11-02)
