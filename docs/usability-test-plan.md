# 사용성 시험 계획 (아직 실행 안 함 — NOT_RUN)

UX 리뷰(2026-11-02, 전문가 관점 리뷰)에서 나온 계획을 정리한 것이다. 지금까지의 UX 판단은 모두 전문가 관점 리뷰이며, 이 시험을 돌리기 전에는 "쓰기 편하다"를 주장하지 않는다.

## 참가자 (5명)

- 친구·동료와 한 달에 한 번 이상 카풀하는 만 18세 이상.
- 평소 운전하는 사람 2명 이상, iOS·Android 섞기, 50대 이상 또는 큰 글씨 사용자 1명 이상.
- 한 사람이 60분 동안 두 역할을 한다: 먼저 **승객**(자기 폰, 진행자가 운전), 다음 **운전자**(에뮬레이터, 공모자 2명이 시험 폰으로 탑승).
- 5명은 흔한 문제를 찾는 규모다. 비율이 아니라 "몇 명 중 몇 명"으로 보고한다.

## 차량 흉내 내기

- 노트북의 Pleos 에뮬레이터를 12–13" 터치 모니터로 미러링해 센터 콘솔 위치(운전석 오른쪽)에 둔다. 뒷좌석 의자는 약 1.2 m 뒤.
- `cd car-app && ./gradlew :app:assembleDebug -Pmoata.webBaseUrl=http://<LAN IP>:3000` 로 빌드해 폰이 QR 로 바로 들어오게 한다. 같은 Wi-Fi.
- 두 번째 진행자가 Virtual Console 로 "운전": 기어 D + 속도(주행 제한 확인), 10초마다 주행거리 +1 km, +16 km 에서 정차(하차), +24 km 도착. 명령은 `DEMO_RUNBOOK.md` §1.
- PLEOS 모드로 한다(DEMO 표기가 붙지 않게). 홈의 `개발자 도구`는 가린다. 도착 때 공모자가 "빨리 가자"며 2분 카드를 보여 준다.

## 성공 지표

- 지시 없이 `탔어요`를 누름(출발 전 또는 +0.5 km 이내): 목표 5/5. 하차 기록 오차 ±0.5 km 이내: 4/5 이상.
- 도착 → 정산안까지 90초 이하. 승객이 길가에서 기다린 시간도 잰다.
- 최종 몫이 정답과 다른 운행 수.
- 이해도 0–3(거리·연료 분배·통행료), 출처 이해 0–4(어떤 값을 사람이 입력했나).
- "묻지 않고 보낼 건가요?" 1–7점, 과제마다 SEQ(한 문항 난이도).
- 오류: 잘못된 거절, 실수로 누른 도착, 오류 배너 뒤 반복 입력.
- D4 시선 2초 이하(영상).

## 관찰할 것

- 가입 후 탭을 닫는지, 닫았다면 다시 찾아오는지.
- `어떻게 계산했어요?`를 여는지.
- 오류 배너 반응, 통행료 분배를 운전자가 어떻게 판단하는지, "주행 중"에 화면을 만지려 하는지.

## 데이터 처리

동의를 받고 에뮬레이터·폰 화면과 방 영상을 녹화한다. 백엔드 감사 시각으로 탑승·하차 km 지연을 잰다. 닉네임만, 가상의 돈만 쓰고 끝나면 모두 지운다.

## 이 계획이 아직 다루지 않는 것 (리뷰가 지적했지만 이번에 고치지 않음)

- 탑승·하차 시점을 운전자가 도착 후 고치는 기능(서버는 운전자 지정 km 를 지원, 화면 없음).
- 통행료를 "그때 타고 있던 사람"끼리만 나누기(지금은 균등·탄 거리 비례·운전자만).
- 도착 때 입력이 몰림(연비는 매번 묻는다 — 수동 연비를 기억하지 않음).
- 차량 화면에서 닉네임·그룹 이름 타이핑.
